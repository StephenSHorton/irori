# Live check 03: v0.3 Capture on Windows

*2026-10-27, Windows 11, Claude Code 2.1.31x, `bin/irori.exe` from `wails3 build` on `v0.3-capture`. Each run used a fresh `IRORI_HOME` and read the real `~/.claude` (read only).*

## Backfill on real data

The headless Core ran over the real `~/.claude/projects`: 3,216 transcript files, with the default 72 h window.
- The first pass finished in about 40 s and settled at about 89 MB of memory and an 11 MB database.
- It logged 705 turns, 437 commit commands, 125 summaries, 41 PR ledger entries and 41 repo roots, including the ww-multiplayer worktrees.
- Before the noise filter there were 5,802 edits, and 5,422 of them were Bash `bashEditDiff` guesses, mostly build output (3,512 `.dll`). The filter now drops these, and its Status counts in one run were artifact 3,615, outside a repo 387, ignored 34 and over the per-call cap 295. Edit and Write edits are never dropped.
- A scan of every row and blob for real token shapes (`sk-ant-`, `gh*_`, `github_pat_`, `xox*-`, `AKIA`, private keys) found none. The scrubber made 10 redactions (assignment, google).

## A session edits and commits

A `claude --bg` session started in the home folder was asked to Write a file in a scratch repo (`core.autocrlf=true`), Edit one line, and commit with `git -C <repo> commit`. The GUI ran at the same time.
- **Edits:** a Write and an Edit, both `exact`, with before and after blob ids.
- **Commit link:** `exact` for the file, both edits linked, the session behind it, and the committer naming that session and turn. The link appeared about 18 s after the commit, during the first-sight catch-up.
- **`why` on the edited line:** blame gives the commit, then the linked edits, then the turn's prompt.
- **Timeline:** the turn with its Write, Edit and Bash chips, then the commit, then the away summary.
- **History tab:** opens on the repo with the newest commit. The commit shows `1 exact`, and expanding it shows `plan.md · 2 edits · exact · Behind it: irori-live-cap4 · 1 turn · committed by irori-live-cap4`.

## Bugs the live runs found (fixed)

1. **The commit was missed when the root was first seen after it.** The tailer reads an edit a few seconds after it is made, and backfill reads it hours later, so the repo's first sighting can come after the commit. Watching started at the end of `logs/HEAD`. On first sight it now starts at the first reflog line at or after that root's oldest captured edit.
2. **The committer was wrong for `git -C <repo> commit` run from outside the repo.** The shell's cwd wasn't under the root, so a different session's command won. Matching now uses the directory named by `git -C` or by a leading `cd` / `Set-Location`.
3. **A fresh install starved the tailer.** With fix 1, the first repo pass walked the backfill window of every root, at two git runs per commit, on the same goroutine as the tailer. New sessions weren't read for minutes. Repo passes now stop after 1.5 s and resume from the same reflog line.
4. **GUI:** History opened on whichever repo loaded first, often one with no commits. A long turn listed every heuristic file. History now follows the newest commit until one is chosen, and a turn lists 8 files (exact edits first) with a "+N more" link.
