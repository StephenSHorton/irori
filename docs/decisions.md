# Decisions

| # | Date | Decision |
|---|---|---|
| 1 | 2026-10-25 | **A new app, built the way Toru is built.** Wails v3 + Go + React/mokei, GitHub Releases, background updates. It is not grown inside suzuri; suzuri stays the terminal. |
| 2 | 2026-10-25 | **An always-on node: yes.** A headless Irori on a Windows desktop holds and forwards messages while other devices are offline. |
| 3 | 2026-10-25 | **Reviving closed sessions: allowed.** When a message arrives for a session that isn't running, Irori can revive it (e.g. `claude --bg --resume`). |
| 4 | 2026-10-25 | **What context to share and sync:** researched in [research/04-context-sharing.md](research/04-context-sharing.md). Recommendation, not yet signed off: replicate structured events plus a redacted, stripped turn index everywhere. Fetch full transcripts, tool output and subagent bodies on demand from the device that recorded them. Sharing or forking full context is an explicit action. Nothing raw is injected into an agent. |
| 5 | 2026-10-25 | **No Discord.** Irori has its own messaging, UI and peer-to-peer transport. |
| 6 | 2026-10-25 | **Name: Irori (囲炉裏).** |
| 7 | 2026-10-26 | **Waking Claude Code through the mod works on Windows.** [Spike 01](spikes/01-mod-wake-windows.md): `$.process.spawn` streams a helper's stdout and `$.prompt.submit` starts a turn in a `--bg` session, which shows it as a plugin message. The mod path is the primary wake; `--resume` stays the fallback for closed sessions. macOS is still to be checked. |
| 8 | 2026-10-26 | **One binary, `irori`:** the desktop app by default, `serve --headless` for the always-on node, `mcp` for agents, `attach` for the mod's stream. Agents find the running instance through `irori.json` in the data dir (`%LOCALAPPDATA%\irori`, `~/.irori`). Wails v3 is pinned at alpha.98 to match Toru; v3.0.0 stable shipped 2026-10-26 and is a separate upgrade. |
| 9 | 2026-10-26 | **Irori messaging sits beside Claude Code's native SendMessage, not over it.** It covers what native can't: Grok and other agents, messages from the person in the GUI, a durable inbox and audit trail, repo-addressed work, and (v0.4) other devices. |
| 10 | 2026-10-26 | **Bypass rule is native's:** a message to a bypass-mode session is held only when the sender isn't also in bypass (or the person, or allow-listed). Every Claude session here runs in bypass, so Claude↔Claude flows and Grok→Claude waits for the person. |
| 11 | 2026-10-26 | **One tools backend, two front ends:** the Core implements the tools; the mod serves them to Claude Code as `mcp__irori__*`, `irori mcp` to Grok as `irori_*`. Claude Code users don't add `irori mcp`. |
| 12 | 2026-10-26 | **"Delivered" means queued in Claude Code** (submit resolved, or pending 3 s), not "its turn started"; a submit that resolves as a drop is not delivered. Engaged = the carrying turn started; answered = the recipient replied. |
| 13 | 2026-10-26 | **Directory leases are strict:** `src` does not cover `src/x`; lease `src/**` for a directory. |
| 14 | 2026-10-27 | **Capture reads the transcripts in the Core; the mod doesn't forward capture.** This reverses research/01 §4 ("`session.append` and `tool.call` feed capture"). Tailing `~/.claude/projects/**/*.jsonl` covers sessions without the mod (all of them today), desktop and older sessions, survives restarts by byte offset, and the transcript already holds `structuredPatch`/`originalFile`. The cost is seconds of lag and an undocumented format, read with an allow-list of record types. [v0.3 design §2](design/v0.3-capture.md). |
| 15 | 2026-10-27 | **Commits link to edits by blob hash, raw and CRLF→LF.** Any reflog movement (including fast-forwards from deleted agent worktrees) brings its commits in; a committed blob equal to an edit's after-blob from any worktree is an exact link. Partial and heuristic links only count edits from the commit's own worktree. |
| 16 | 2026-10-27 | **The Board replaces the Work tab.** Tasks, blockers and people's comments in one view; a lease shows as a card when it blocks something. Prototype: the "Irori Board" artifact. |
| 17 | 2026-10-27 | **Blocked is a task state with a reason, not a card of its own.** A blocker with no task behind it (a port held by a dead dev server) becomes a small task in the blocked state. |
| 18 | 2026-10-27 | **A person's comment reaches the agent at its next turn by default; waking it is a choice per comment.** A wake is a full turn that re-reads the agent's context, so the default costs nothing extra. |
| 19 | 2026-10-27 | **Anyone, agent or person, can close a blocker.** |
| 20 | 2026-10-27 | **Anyone on a shared task can work it** (several holders). File leases stay the guard against two agents editing the same files, and a shared task warns when its members' leases overlap. This relaxes v0.2's single-writer rule for shared tasks only. |
| 21 | 2026-10-27 | **Agents can assign tasks to each other;** the assignee hears at its next turn. |
| 22 | 2026-10-27 | **Connected people are people on paired devices (v0.4), each with their own name;** opening Irori to more people (collaborators with their own machines) with public and private work kept apart is being designed separately. |
| 23 | 2026-10-27 | **Agent autonomy is each person's setting, per board, with safe defaults.** Presets Ask me (default) / Trusted / Autonomous plus individual switches: create board tasks, share private tasks, assign across people, mirror leases. It governs only what your own agents may do; others' agents reaching yours stays under your receive-side allow-lists. It can be changed only in the app, never by a tool, and nothing that never leaves the device (transcripts, keys, policy, patches) becomes shareable under any preset. [research/06](research/06-multi-person.md). |
| 24 | 2026-10-27 | **What reaches your agents from other people is also your setting, up to full wakes.** Per board and per person: Open (the default: anyone on the board and their agents wake yours, since boards only hold people you invited and confirmed) / Members wake (people you pick) / Ask me (wake requests and bypass rows held) / Closed (everything at the next turn). Who joins a board is the person's responsibility; Irori adds no warning on top (Stephen, 2026-10-27). This makes cross-person, event-driven autonomy (agents waking each other through the mod and Claude's channels push) a supported mode, not an exception. The hop limit, rate limit and Pause all stay on under every setting; there is no token budget (Stephen, 2026-10-27). |
| 25 | 2026-10-27 | **The Board is a scratch pad for live coordination, not a tracker.** It has no priorities, estimates, sprints, labels or backlog, and no retention timers: cards stay until they are done or closed. Agents are told, in the tool descriptions, not to keep long-term information there and to use whatever the project already uses (Linear, Notion, GitHub issues, docs), linking to it from the card. Irori points to trackers and never mirrors them. [design/board.md](design/board.md). |
