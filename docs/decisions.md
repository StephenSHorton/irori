# Decisions

| # | Date | Decision |
|---|---|---|
| 1 | 2026-10-25 | **A new app, built the way Toru is built.** Wails v3 + Go + React/mokei, GitHub Releases, background updates. It is not grown inside suzuri; suzuri stays the terminal. |
| 2 | 2026-10-25 | **An always-on node: yes.** A headless Irori on a Windows desktop holds and forwards messages while other devices are offline. |
| 3 | 2026-10-25 | **Reviving closed sessions: allowed.** When a message arrives for a session that isn't running, Irori can revive it (e.g. `claude --bg --resume`). |
| 4 | 2026-10-25 | **What context to share and sync:** researched in [research/04-context-sharing.md](research/04-context-sharing.md). Recommendation, not yet signed off: replicate structured events plus a redacted, stripped turn index everywhere. Fetch full transcripts, tool output and subagent bodies on demand from the device that recorded them. Sharing or forking full context is an explicit action. Nothing raw is injected into an agent. |
| 5 | 2026-10-25 | **No Discord.** Irori has its own messaging, UI and peer-to-peer transport. |
| 6 | 2026-10-25 | **Name: Irori (囲炉裏).** |
| 7 | 2026-10-26 | **Waking Claude Code through the mod works on Windows.** [Spike 01](spikes/01-mod-wake-windows.md): `$.process.spawn` streams a helper's stdout and `$.prompt.submit` starts a turn in a `--bg` session, which shows it as a plugin message. The mod path is the primary wake; `--resume` stays the fallback for closed sessions. macOS is still to be checked. |
| 8 | 2026-10-26 | **One binary, `irori`:** the desktop app by default, `serve --headless` for the always-on node, `mcp` for agents, `attach` for the mod's stream. Agents find the running instance through `irori.json` in the data dir (`%LOCALAPPDATA%\irori`, `~/.irori`). Wails v3 is pinned at alpha.98 to match Toru; v3.0.0 stable shipped 2026-10-26 and is a separate upgrade. |
| 9 | 2026-10-26 | **Irori messaging sits beside Claude Code's native SendMessage, not over it.** It covers what native can't: Grok and other agents, messages from the person in the GUI, a durable inbox and audit trail, repo-addressed work, and (v0.4) other devices. |
| 10 | 2026-10-26 | **Bypass rule is native's:** a message to a bypass-mode session is held only when the sender isn't also in bypass (or the person, or allow-listed). Every Claude session here runs in bypass, so Claude↔Claude flows and Grok→Claude waits for the person. Amended by decision 34: the person's own Claude agents on any of their devices are never held for it. |
| 11 | 2026-10-26 | **One tools backend, two front ends:** the Core implements the tools; the mod serves them to Claude Code as `mcp__irori__*`, `irori mcp` to Grok as `irori_*`. Claude Code users don't add `irori mcp`. |
| 12 | 2026-10-26 | **"Delivered" means queued in Claude Code** (submit resolved, or pending 3 s), not "its turn started"; a submit that resolves as a drop is not delivered. Engaged = the carrying turn started; answered = the recipient replied. |
| 13 | 2026-10-26 | **Directory leases are strict:** `src` does not cover `src/x`; lease `src/**` for a directory. |
| 14 | 2026-10-27 | **Capture reads the transcripts in the Core; the mod doesn't forward capture.** This reverses research/01 §4 ("`session.append` and `tool.call` feed capture"). Tailing `~/.claude/projects/**/*.jsonl` covers sessions without the mod (all of them today), desktop and older sessions, survives restarts by byte offset, and the transcript already holds `structuredPatch`/`originalFile`. The cost is seconds of lag and an undocumented format, read with an allow-list of record types. [v0.3 design §2](design/v0.3-capture.md). |
| 15 | 2026-10-27 | **Commits link to edits by blob hash, raw and CRLF→LF.** Any reflog movement (including fast-forwards from deleted agent worktrees) brings its commits in; a committed blob equal to an edit's after-blob from any worktree is an exact link. Partial and heuristic links only count edits from the commit's own worktree. |
| 16 | 2026-10-27 | **The Board replaces the Work tab.** Tasks, blockers and people's comments in one view; a lease shows as a card when it blocks something. Prototype: the "Irori Board" artifact. |
| 17 | 2026-10-27 | **Blocked is a task state with a reason, not a card of its own.** A blocker with no task behind it (a port held by a dead dev server) becomes a small task in the blocked state. |
| 18 | 2026-10-27 | **A person's comment reaches the agent at its next turn by default; waking it is a choice per comment.** A wake is a full turn that re-reads the agent's context, so the default costs nothing extra. |
| 19 | 2026-10-27 | **Anyone, agent or person, can close a blocker.** |
| 20 | 2026-10-27 | **Anyone on a shared task can work it** (several holders). File leases stay the guard against two agents editing the same files, and a shared task warns when its members' leases overlap. This relaxes v0.2's single-writer rule for shared tasks only. |
| 21 | 2026-10-27 | **Agents can assign tasks to each other;** the assignee hears at its next turn. |
| 22 | 2026-10-27 | **Connected people are people on paired devices (v0.4), each with their own name;** opening Irori to more people (collaborators with their own machines) with public and private work kept apart is being designed separately. |
| 23 | 2026-10-27 | **Agent autonomy is each person's setting, per board, with safe defaults.** Presets Ask me (default) / Trusted / Autonomous plus individual switches: create board tasks, share private tasks, assign across people, mirror leases. It governs only what your own agents may do; others' agents reaching yours stays under your receive-side allow-lists. It can be changed only in the app, never by a tool, and nothing that never leaves the device (transcripts, keys, policy, patches) becomes shareable under any preset. [research/06](research/06-multi-person.md). |
| 24 | 2026-10-27 | **What reaches your agents from other people is also your setting, up to full wakes.** Per board and per person: Open (the default: anyone on the board and their agents wake yours, since boards only hold people you invited and confirmed) / Members wake (people you pick) / Ask me (wake requests and bypass rows held) / Closed (everything at the next turn). Assignments from other people follow the same setting, so on Open they are delivered like comments. Who joins a board is the person's responsibility; Irori adds no warning on top (Stephen, 2026-10-27). This makes cross-person, event-driven autonomy (agents waking each other through the mod and Claude's channels push) a supported mode, not an exception. The hop limit, rate limit and Pause all stay on under every setting; there is no token budget (Stephen, 2026-10-27). |
| 25 | 2026-10-27 | **The Board is a scratch pad for live coordination, not a tracker.** It has no priorities, estimates, sprints, labels or backlog, and no retention timers: cards stay until they are done or closed. Agents are told, in the tool descriptions, not to keep long-term information there and to use whatever the project already uses (Linear, Notion, GitHub issues, docs), linking to it from the card. Irori points to trackers and never mirrors them. [design/board.md](design/board.md). |
| 26 | 2026-10-27 | **New boards default to Trusted autonomy** (agents create board tasks; sharing a private task is a request). **Requests reach the person as actionable notifications, not chat text:** a notification in front of other programs, styled after Toru's (the toru-notifications work), with Share / Review / No buttons, on every device the person is on (v0.4), cleared everywhere once answered. The Board's "Needs you" lane and a tray count back it up. The requesting agent doesn't wait: the answer reaches it at its next turn. Approvals are the first use of Irori notifications. |
| 27 | 2026-10-27 | **Irori holds live, unresolved state and lets it go.** Its power is knowing what's underway, blocked or waiting, across agents and machines. Long-lived knowledge belongs in the project's own docs and trackers. So decision records leave Irori: the `decision_record` and `decisions` tools are removed, and `why` keeps only what capture records by itself (commits, edits, the turns behind them). Existing decision rows stay in the log, unread. |
| 28 | 2026-10-27 | **Agents send files and data across machines and to other people's agents.** Files are attachments on messages and Board cards, carried over Irori's device connection (v0.4; go-room since decision 31), fetched by the receiver when needed, to your own devices or to a shared board's members. This is part of v0.4's design, not an add-on. |
| 29 | 2026-10-27 | **Peer review across people.** On a shared board, an agent can ask another person's agents to review a PR. A board member can dedicate an agent as a reviewer for a board or repo, and requests route to it. The review is posted by the reviewer's own `gh`, under its owner's GitHub account, because a review from the PR author's account doesn't count (and can't approve). Irori carries the request and shows its state (asked, reviewing, approved, changes requested) from the PR ledger; it never posts reviews or merges itself. Your own agents can comment but aren't offered as approvers. Lands with Shared Boards (v0.4). |
| 30 | 2026-10-27 | **v0.4 Devices choices (design/v0.4-devices.md §12), all as recommended:** a full mesh, with no hub; keys held in Windows DPAPI and the macOS Keychain; the always-on node runs the normal desktop app in the tray, keeping updates; the signed macOS release job is in scope; Pause all stays per device; 256 MiB per attachment, fetched on demand; the person key rotates automatically when a device is removed; agents' last-message text stays on its own device; only the GUI gets the all-devices view of the local API, never anything that just reads `irori.json`. The window becomes cards only and ships first as v0.3.3 (D7). |
| 31 | 2026-10-27 | **v0.4 links devices with Toru's pure-Go stack, not an iroh sidecar.** pion WebRTC data channels, signaling over public MQTT brokers sealed with a key derived from the pairing code (as Toru's rooms do), and STUN, plus an optional TURN relay setting for networks that block direct connections. It is extracted from Toru into a shared public module, `github.com/StephenSHorton/go-room`, which both apps use (as with go-toast). This means one toolchain, no helper process to build and sign on macOS, and a stack already proven on Stephen's machines. The trade-off against iroh: a machine that can't connect directly needs a TURN relay, where iroh had n0's free relays. design/v0.4-devices.md §4 is revised to match. |
| 32 | 2026-10-28 | **Shared Boards (research/06) picks.** Boards are private (your devices only) or shared (people you invite, and their agents); there are no boards open to strangers, since that would need an always-on host and Irori runs no server. A shared board is a named group of people around any topic, not tied to a repo (06 decision 1 overridden): leases and PR links still work on it, and you can have several boards with the same person, each separate from your private board. The rest as recommended: any owner invites and removes, with several owners allowed (7b); only leases of agents working shared tasks are mirrored (6a); your always-on node stores and forwards board rows (9a); other people see only commit SHAs and PR URLs cited by shared tasks, with "share this turn" extracts later (10a, then b); no board-log encryption beyond the transport until a board has a third person (11a). Already settled elsewhere: receive Open (24), Trusted autonomy (26), assignments follow receive, the person key on all devices (30), next-turn delivery via the mod (spike 04). Building starts after the PC and Mac pair on v0.4. |
| 33 | 2026-10-28 | **The always-on PC is Irori's server; the public MQTT brokers are removed from Irori entirely.** Stephen: "irori needs a persistent running instance of itself in order to coordinate between any nodes connecting ... Make this computer that server." There is no automatic or opt-in broker fallback, and no public STUN. The always-on node (D3(a), the normal desktop app in the tray) runs the home server: a signaling hub for the sealed envelopes (TLS, admitting only this person's certified devices, plus guests for an open pairing window), a TURN relay with short-lived credentials issued over the hub, and UPnP-IGD/NAT-PMP port mapping, publishing its addresses in a replicated `node.addr` row. Devices on one network also find each other directly with sealed LAN datagrams, so two of them sync with the server off. With the server off, a device away from home can't connect; Stephen accepts that. No dynamic-DNS service. The data path stays the mesh of decision 30: the hub only introduces devices, and rows still travel device to device. This supersedes row 31's broker signaling and public STUN, and row 32's "Irori runs no server". go-room keeps its broker signaler as a separate `mqtt` package for Toru and gains carriers, the LAN carrier, the hub, a TURN server and port mapping (v0.2.0). [design/v0.4-devices.md](design/v0.4-devices.md) §4.2, §4.4, §7, §8, §11 (Release 3b). |
| 34 | 2026-10-28 | **The person's own agents are never held for `bypass_receiver`, on any of their devices.** Amends decision 10. Found at the first real PC+Mac pairing: Claude sessions on the Mac messaged and assigned Board tasks to a bypass session on the PC, most Mac cards read `permissionMode` unknown (non-bypass), and every message was held, each with its own notification card. Stephen: his own agents are treated like him. A sender skips the hold when it is a Claude agent (kind `claude`, not a Grok card) whose key's device is this device or a device certified to this person and not revoked, and is the device that wrote the message (one device can't claim another's agent); the host decides, as before (v0.4 §6.3). This includes a prompting session on the same device: a session that read untrusted content can now have a bypass session run its instructions without a prompt, the risk decision 10's hold used to catch. That follows from treating own agents like him; flagged for Stephen to confirm. The sender's own bypass mode likewise counts only when its key's device wrote the message. The hold stays for Grok members, agents on unknown or removed devices, and other people's agents (Shared Boards). The block list, allowlist mode, Pause all, the hop limit and the rate limit apply to own agents as before. Held-message notifications also coalesce to one card per sender, updated in place with a count. [design/v0.2-talk.md](design/v0.2-talk.md) §5, [design/v0.4-devices.md](design/v0.4-devices.md) §6.3. |
| 35 | 2026-10-28 | **v0.5 Shared Boards choices ([design/v0.5-shared-boards.md](design/v0.5-shared-boards.md) §13), as recommended.** B1: every member's home server admits that board's members' certified devices, for that board's topics only, with TURN that reaches only the server's relayed addresses; members learn the server's public address, their peers' current addresses and device counts. This widens decision 33's hub admission. B2: on Open, other people's rows reach your bypass sessions; Ask me and Closed hold them. This amends decision 34: its "the hold stays for other people's agents" applies under Ask me and Closed only. B3: private cards keep `#12`; shared cards are `<tag>#12` (`mlg#12`), with a tag picked at board creation; a bare number works only when unique across every board. B4: invites are a pasted link (code, server address, person fingerprint); the invitee reads five words aloud on a voice call for the inviter to type, and both read out each other's fingerprints. |
